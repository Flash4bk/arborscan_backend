## Реально выполнено

Пользователь сменил пароль БД и записал его в приватный `.pgpass`. Агент не менял
пароль, не выводил реквизиты и не перезаписывал `.pg_service.conf`/`.pgpass`.
Права обоих файлов проверены (600). `SELECT 1` через `service=arborscan_backup`
успешен, включая повтор через установленный клиент с полной проверкой TLS.

На VPS установлены пользовательские обёртки `/home/arborscan/.local/bin/psql`,
`pg_dump`, `pg_restore`. Они запускают клиенты **17.11**, совместимые с сервером
**17.6**, из закреплённого образа:

`postgres@sha256:d74eeac9a635390a49bc21bd49fccd973de707e2a53a76ac49b552b8712ec46f`.

Sudo не понадобился, сервер PostgreSQL на хост не установлен. Для уже открытой
SSH-сессии, где `~/.local/bin` ещё отсутствует в PATH:

```sh
export PATH="$HOME/.local/bin:$PATH"
psql -w 'service=arborscan_backup' -c 'select 1'
pg_dump --version
pg_restore --version
```

Обёртки подставляют `sslmode=verify-full` и публичный CA Supabase для данного
service. Системный CA bundle не доверял Supabase Root 2021 CA, поэтому сертификат
получен по HTTPS с
`https://supabase-downloads.s3-ap-southeast-1.amazonaws.com/prod/ssl/prod-ca-2021.crt`
в `/home/arborscan/supabase-ca.crt`. SHA-256 fingerprint сертификата:
`807025AD50D4ED219D2C9C7D299C004F824EB00CF7F65AFEF607D07B72E6CAFA`.
Проверка имени сервера и CA не отключалась при создании дампа. `pg_stat_ssl`
через pooler описывает его внутреннее соединение и возвращает false; это не
состояние клиентского TLS. Первоначальный SELECT 1 с настройками пользователя
не выдаётся за проверку сертификата; последующие команды требуют verify-full явно.

  **52153976 байт** проверено. Секретные данные/дампы в Git не добавлялись.

Незавершённые ранние попытки сохранены отдельно без COMPLETE. Нативная копия
не содержит байтов Storage, образов Docker, внешней конфигурации Supabase и

Согласованность транзакций pg_dump относится к одной базе. Роли, Storage и дамп
снимаются последовательно, общей транзакции между ними нет. Для проверенных
снимков совпадение девяти связей проверено явно; активные записи во время будущего
backup могут потребовать нового согласованного снимка. Дамп содержит приватные
данные приложения/Auth и должен оставаться в закрытом хранилище.
