данные приложения/Auth и должен оставаться в закрытом хранилище.

## Сквозной запуск восстановленного приложения — 28.09.2026

Источник всех данных: `ops-backups/20260928T133059Z`, проверенный общий manifest.
Среда: `/home/arborscan/as14-recovery-20260928T135137Z`, отдельный compose project,
volumes DB/Storage/runtime и внутренняя сеть. Единственный внешний интерфейс —
шлюз `127.0.0.1:18080`; API/БД/Storage/worker находятся во внутренней сети.
Попытка TCP-соединения тестового API с публичным production:443 отклонена сетью.
Шлюз имеет отдельную bridge-сеть для localhost-порта и фиксированные upstream,
произвольное проксирование наружу не настроено.

Фактические зависимости:

| Компонент | Назначение и проверенная версия |
|---|---|
| Копия API v3 | Собственная авторизация ArborScan через public.users/auth_sessions; образ a34400f / ID 5a0b1d63… |
| API v4 | Отчёты, контуры, inference; reliability-691fb77 / ID afb6c578… |
| PostgreSQL | 17.6.1.063, полный native restore с ролями/ACL |
| PostgREST | v14.17, REST и RPC к восстановленной базе |
| Storage API | **v1.79.20**, настоящий file backend, отдельный volume |
| Nginx | 1.28-alpine, локальный шлюз REST/Storage/API |
| Worker | Тот же образ reliability-691fb77, отдельный runtime/heartbeat |

Полные digest всех семи сервисов: `evidence/as14/as14-recovery-stack.json`.
Supabase GoTrue не заменяется базой: для проверенного входа ArborScan он **не нужен**,
поскольку приложение использует свои auth-маршруты v3. Studio, Realtime, Edge
Functions и imgproxy не входят в фактические зависимости проверенного цикла.
Внешние Google sign-in, PlantNet, погода и Vault/KMS не проверялись в offline lab.

Все JWT/service keys и пароли сервисов созданы заново только для lab. Production
env, `.pgpass` и SSH-ключи не монтировались. Сессии и активные задания в **копии**
БД обезврежены до запуска; исходный дамп не менялся. Использованы прежние модели
из local-files.tar, автоматическая смена модели не включалась. Runtime образов
брали из локального Docker-хранилища VPS: проверка не имитировала потерю всех
образов на совершенно новом хосте. Для такого переноса нужны указанные образы
(или отдельный `docker save`/`docker load`); приватные образы не опубликованы в registry.

Обнаруженные и исправленные проблемы сборки lab:

- права нового volume PostgreSQL требуют владельца postgres;
- соединения между контейнерами требуют отдельного pg_hba и новых паролей;
- Storage v1.74.0 из стандартного self-hosted compose несовместим со схемой
  миграции 72 в дампе: SQLSTATE 42P10. Применён опубликованный v1.79.20, схема
  production не менялась, ограничение уникальности не ослаблялось;
- worker требуется проверять по heartbeat, а не унаследованным HTTP health API.

Реально выполненные проверки приложения:
