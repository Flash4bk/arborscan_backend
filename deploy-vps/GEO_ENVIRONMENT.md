## Контракт и права

Используется существующая серверная история: `POST /v4/reports`,
`GET /v4/reports`, `GET /v4/reports/{version_id}` и
`GET /v4/reports/capabilities`. Последний объявляет `environment_version: 1`.
Новый независимый запрос — `GET /v4/environment?lat=<lat>&lon=<lon>`.
Все запросы используют прежний `Authorization: Bearer` и проверку текущего
пользователя на сервере. Условия возвращаются с `Cache-Control: private, no-store`
и `Vary: Authorization`. Клиент не может задать произвольный URL провайдера.

При стандартной конфигурации полный внешний маршрут:
`https://31.57.170.88/api/v4/v4/environment`. Повтор `v4` намеренный: Nginx снимает
только внешний `/api/v4/`. Базовые адреса остаются в ApiConfig с прежними
`ARBORSCAN_V3_BASE_URL` и `ARBORSCAN_V4_BASE_URL`; проверка TLS не отключается.

Необязательное поле `snapshot.environment` имеет такой смысл:

```text
version: 1
gps: null или {
  value: {lat, lon, crs: "EPSG:4326"},
  source: "exif" | "device" | "manual",
  retrieved_at, observed_at: null | ISO-время с зоной,
  accuracy_m: null | неотрицательное число,
  is_last_known: bool,
  position_kind: "camera_or_device" | "tree",
  captured_local?: время EXIF без выдуманной зоны,
  is_approximate?: bool
}
weather: null или снимок текущих данных OpenWeather / причины недоступности
soil: null или снимок модельной сетки SoilGrids / причины недоступности
```

Сервер проверяет структуру, допустимые поля/провайдеры, единицы, конечные числа,
диапазоны lat ±90/lon ±180, временные метки и совпадение request_point условий
с GPS выбранной версии. **Нулевая компонента координат допустима**. Отсутствующий
GPS не превращается в `(0, 0)`. Внутренний центр обзора карты не является точкой
обследования. Значения снимка предоставлены клиентом и не получают статуса
независимо измеренных только от успешного сохранения.

Изменение места/условий создаёт дочернюю неизменяемую версию с
`change_source=environment_edit`. Фото, измерения, эталон, AR и ссылка на контур
копируются из выбранной версии. Открытие истории/карты/PDF не делает нового
запроса к провайдерам. Смена точки удаляет прежние условия; поздний ответ
проверяется по поколению запроса и сессии. Сохранение копирует снимок: последующее
завершение запроса не изменяет сохранённую версию. Повторы и конфликт родительской
версии используют прежние серверные механизмы истории; ошибка оставляет черновик.

## Источник координат и ограничения

На S24 с финальным +12 агент отдельно выполнил явный запрос GPS: реально
полученные координаты проверены приватно на диапазон, диалог показал время,
возраст и доступную accuracy. После «Отмена» осталась исходная ручная DEMO-точка;
положение устройства не применено/не сохранено на сервере. Личные координаты
и экран диалога не опубликованы: [факты без координат](evidence/as15-as09/s24-device-gps-check.json).

- **EXIF** читается из исходных JPEG-байтов до обработки изображения. Проверяются
  DMS и обозначения полушарий; ориентация изображения и геометрия разметки этим
  чтением не меняются. EXIF обычно описывает положение камеры, а не основания
  дерева. Точность, которой нет в файле, не выдумывается. Если зона времени
  отсутствует, время сохраняется в `captured_local`; UTC-наблюдение не сочиняется.
  Текущая реализация не извлекает GPS из HEIC/PNG; ручной выбор остаётся доступен.
- **Устройство** запрашивается явным действием. Диалог показывает время/возраст,
  доступную accuracy и последнее известное/приблизительное положение; применение
  требует подтверждения. Фото из прошлого не получает текущий GPS автоматически.
  Положение устройства может отличаться от положения дерева.
- **Ручная точка дерева** задаётся на карте или координатами. Источник сохраняется
  как manual/tree; заявление о метрологической точности не добавляется.
- Разрешение Android только для использования приложения; отказ, ограниченная
  точность, выключенная геолокация и отсутствие положения не блокируют фотоанализ.
  Сохранённые обследования с координатами доступны без получения нового GPS.

## Что хранится и что переживает смену окружения

| Данные | На устройстве | На сервере | Перезапуск / выход / переустановка / другое устройство |
|---|---|---|---|
| Новое фото, AR-сессия и ещё не сохранённый выбор места на главной до получения отчёта | Состояние текущего экрана | Нет | Не обещается восстановление этой стадии после остановки; live AR/tracking не восстанавливается из отчёта |
| Полный отчёт после создания локального journal, включая фото и environment | `report-history-v1`, папка владельца | Только после подтверждённого upload | Перезапуск сохраняет; при выходе скрыт другому аккаунту; удаление данных/переустановка/смена телефона теряет локальную копию |
| Черновик новой версии места/условий | Тот же journal; сохраняется при изменениях | Нет до успешного сохранения | Перезапуск/пересоздание сервиса сохраняет; доступен исходному аккаунту; сам по себе между устройствами не переносится |
| Эталон, исходное фото, точки, длина/единица, условия | `reference-measurements-v1`, папка владельца | Только явно сохранённая версия серверного отчёта | Локальное восстановление после перезапуска; выход не делает чужие данные доступными; переустановка теряет локальный черновик |
| Подтверждённая серверная версия отчёта с оригиналом и снимком условий | Journal и, после открытия, `report-cache-v1` | Прежние закрытые Storage + индекс версий с owner | Повторный вход/переустановка/другой телефон: загружается после входа в тот же аккаунт и при доступном сервере; локальный черновик автоматически не мигрирует |
| Индекс карты и ранее открытые серверные версии | Кеш по владельцу; точная версия и оригинал | Источник — серверная история | Кеш переживает перезапуск и изолирован при выходе; отсутствующий кеш после переустановки требует сети |
| Ответ провайдера до сохранения | В текущем controller | Короткоживущий память-кеш API | Кеш API исчезает при перезапуске процесса; это не сохранённые погодные условия обследования |
| Экспортированный через Android файл PDF | В выбранном пользователем файловом хранилище | Не загружается автоматически | Жизненный цикл определяется выбранным хранилищем; экспорт не является синхронизацией черновика |

Локальные папки по аккаунтам дают **изоляцию**, а не синхронизацию между
устройствами. Logout не объявляется удалением локальных файлов. Поздние ответы
предыдущей сессии блокируются; следующий пользователь не получает его кеш,
черновики или маркеры. Кеш не выдаёт права на запросы сервера и не подменяет
отказ 401/403/404. Автоматическая резервная копия Android не является контрактом
восстановления после переустановки; на неё приложение не полагается.

## Карта и карточка обследования

Сохранён существующий Google Maps. Карта собирает доступные текущему владельцу
локальные отчёты, серверные версии v4, совместимые старые v3-записи и кеш.
Локальная/серверная копия сохранённой версии исключается по **точному
version_id**. Дополнительное узкое правило `mergeSurveyVersions` подавляет
автоматическую сводку `legacy-local` с `environment_snapshot` и совпадающим
`metadata.analysisId` только при наличии полной исходной версии с непустыми
version_id/analysisId, `snapshot.kind=v4`, `snapshot.change_source=analysis`
и той же парой `(owner, analysisId)`. Это fallback исходного анализа, а не
самостоятельная сохранённая версия; реальные ревизии, эталонные отчёты и разные
наблюдения не исключаются этим правилом. Порода или близость точек не являются
основанием объединения.
При совпадающей точке предлагается выбор отдельной записи. Постоянный ID дерева
или связь разных обследований с одним физическим деревом не заявлены.

Карточка содержит реальное фото, вид со статусом именно выбранной версии,
дату, доступные размеры, координаты и переход к нужной версии; происхождение
и условия раскрываются отдельно. Маркеры и счётчики строятся из данных.
Цвет не кодирует неподтверждённый научный риск. Для старого отчёта без координат
предлагается добавить точку в новую версию; общая карта других записей доступна.

Слои normal/hybrid, 3D и переход Street View сохранены. Без сети доступен список
сохранённых данных/кеш точных версий; **офлайн-пакет картографических плиток не
реализован**. Доступность внешнего Maps/Street View зависит от приложения/сети.
Google Maps SDK настроен существующим ключом; обычная подложка реально загружена
на S24 +8. На AVD +10 реально отрисованы спутник и 3D с возвратом в обычный 2D;
две совпадающие точки открыли chooser отдельных точных version_id и нужную
карточку. На S24 +10 кнопки слоя/3D меняют режим, но плитки в свежей попытке
не загрузились. Переход Street View на S24 +10 подтвердил native intent
`google.streetview`, запуск Google Maps и возврат Back; целевая точка и панорама
не подтверждены, браузерный fallback не использовался. 3D-наклон карты не
является объёмной моделью дерева или проверкой геометрии.
Права/ограничения ключа в Google Cloud Console этим локальным запуском не
аудированы. Не включались новые услуги/биллинг. Требования: [настройка Flutter](https://developers.google.com/maps/flutter-package/config)
и [ограничения API-ключей](https://developers.google.com/maps/api-security-best-practices),
проверены по официальной документации 05.10.2026.

## Провайдеры, единицы, ожидание и ограничения

**Погода:** сохранён OpenWeather Current Weather `/data/2.5/weather`, `units=metric`.
Контракт поддерживает температуру °C, ветер/порывы м/с, метеорологическое направление
°, давление hPa, влажность %. `data_at` берётся из UTC `dt`; время получения
отдельное. Пропущенный порыв/поле остаётся отсутствующим. Запрос описывает текущие
данные провайдера по точке, не условия съёмки старого фото и не измерение у дерева.
