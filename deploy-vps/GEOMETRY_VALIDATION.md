# AS-08 / AS-13: геометрия и полевая проверка

Рабочая ветка `codex/geometry-validation` создана поверх `ce3f364` пакета
model-quality. Main не меняется. Программная проверка не является полевой
валидацией; результаты телефона и точные версии выкладки фиксируются ниже по факту.

## Показатели и фактические методы

Все фото-точки относятся к исходному EXIF-ориентированному изображению без crop:
`normalized_oriented_image`, координаты [0,1], размеры W,H. Вектор пикселей
v=(dx*W,dy*H); r — вектор вертикального эталона, e=r/|r|,
s=L/|r| м/px. Zoom/pan экрана не входит в формулы. Высота эталона — введённая
пользователем высота именно отмеченного отрезка, не предположение по виду объекта.

| Показатель | Входы и формула | Единицы / источник | Статус и ограничения |
|---|---|---|---|
| Высота дерева по эталону | Основание/вершина: abs(v·e)*s | м, reference v1/v2 | Реализована проекционная вертикальная высота; не длина ствола. Эталон должен быть вертикальным, в той же глубине; перспектива не исправляется |
| Прямой отрезок основания–вершины | norm(v)*s, отдельно от высоты | м, reference v2 | Добавлен; не длина кривой оси ствола |
| Высота по маске + explicit scale | (ymax-ymin+1)*s | м, fusion v2 | Сохранён совместимый результат, исправлена подпись: вертикальный размер маски на фото, не высота по тяжести. Roll камеры меняет эту величину |
| AR-высота | y(top)-y(base), луч в фиксированную вертикальную плоскость дерева | м, AR world, fixed_vertical_tree_plane_ray_intersection_v1 | Реализовано ранее; вертикальная координата ARCore, предположение плоскости. Полевой точности нет |
| Ширина кроны | Ручные края именно кроны: abs(v×e)*s | м, reference | Одна проекционная ширина, не средний диаметр/объём. Для API без ручного crown_width_px — метрическая крона недоступна. Pixel crown_width_px — лишь 95-й процентиль ширин верхних 88% общей маски |
| Высота кроны | Отмеченные нижняя граница живой кроны/верх: abs(v·e)*s | м, reference v2 | Добавлена ручная проекционная величина; отдельная автоматическая сегментация кроны отсутствует |
| Диаметр в отмеченном сечении | Края коры d, локальная ось a: abs(d×a)/norm(a)*s | м, reference v2 | Добавлена ширина сечения, фотооценка диаметра при круглом сечении. Не инструментальный замер; уровень середины сечения относительно отмеченного основания сохраняется отдельно |
| AR-диаметр | 2*distance_to_axis*sin(angle_between_tangent_rays/2), медиана 3 повторов | м, cylindrical_tangent_rays_median_v2 | Вертикальный цилиндр, фактическая высота и лучи в provenance. Coach около 1,3 м ±12 см — допуск интерфейса, не доказанная погрешность и не правило DBH |
| DBH | Требует полевого выбора основания/места по методике | м | Исправлен дефект: скаляр 1,3 м больше не назначает standard=dbh_1_3m. Диаметр остаётся доступен под своим названием, DBH=null с причиной |
| Наклон участка ствола | atan2(abs(a×e),abs(a·e))*180/pi | градусы, reference v2 | Добавлен острый 2D-угол к вертикальному эталону, а не к краю снимка. Учитывается выбранный прямой участок; кривизна и 3D-наклон не определяются |
| Пористость кроны | Проверенной области/маски просветов нет | безразмерная | Недоступна с причиной. Заполненный полигон и единая маска дерева недостаточны. Нет подстановки по породе, нет аэродинамической интерпретации |

## Методические первоисточники

- [FAO, National forest inventory field manual, §6.2.1](https://www.fao.org/4/ae578e/ae578e06.htm): диаметр поверх коры, перпендикулярно оси; базовый уровень 1,3 м, на уклоне отсчёт сверху. Для наклона, развилок и неровностей предусмотрены особые положения. Эта методика не сводится к сравнению числа с 1,3. Приложение не подтверждает такие условия автоматически и не присваивает DBH по фото/AR.
- Toney, C.; Reeves, M.C. (2009), *Equations to convert compacted crown ratio to uncompacted crown ratio for trees in the Interior West*, Western Journal of Applied Forestry 24(2), 76–82, [DOI / первичная карточка USDA](https://research.fs.usda.gov/treesearch/32620). Различаются естественная и мысленно уплотнённая крона. Здесь пользователь отмечает видимые границы живой кроны **без мысленного переноса ветвей**; это проекционный размер, не заявленное соответствие полной полевой процедуре FIA и не её crown ratio.

## От разметки до истории

`ReferenceMeasurement` v2 хранит прежние reference/tree/crown/outline плюс
crown_height/trunk/trunk_axis, систему координат, W/H, длину и происхождение масштаба.
Каждая новая величина содержит value/unit/method/source/definition/limitations/reason.
Отсутствие — null; нулевой угол допустим. API пересчитывает v2 из точек, не доверяет
присланным числам geometry. Фото проверяется по реальным ориентированным размерам.
Серверная история сохраняет исходные байты и SHA256, неизменяемый снимок и родителя;
существующие owner/UUID/conflict/повтор механизмы не заменены. SQL-миграция не нужна.
Ни разметка, ни сохранение отчёта не принимает контур и не меняет модерацию.

Старый v1 читается прежним методом; дополнительные данные не выдумываются.
Экран серверной записи показывает сохранённые числа, без автоматического пересчёта.
Действие «Изменить эталон / новая версия» восстанавливает также новые точки;
старые корректные точки эталона повторно ставить не нужно. Правка создаёт ребёнка.
Старый клиент продолжает отправлять v1. Он не понимает редактирование reference v2;
после отката APK новые версии остаются на сервере, для их правки нужен новый клиент.
Новый клиент проверяет reference_versions в capabilities; старый сервер не получает
неподдерживаемый v2, черновик остаётся на устройстве с понятным сообщением.

Локальная разметка и неотправленная версия живут только в каталоге аккаунта на
устройстве, переживают остановку/выход и повторный вход тем же аккаунтом. Очистка
данных/удаление приложения/другой телефон их не восстанавливает. После явного
сохранения в аккаунте серверная версия доступна другим устройствам того же владельца.
AR остаётся отдельным прямым измерением: его масштаб не переносится на фото;
SHA256 + подтверждение пользователя связывают запрос с фото, но не доказывают
физическое совпадение дерева. Расчёт β, обучение и модели не изменены.

## AS-13: один полевой протокол

1. Сначала доступный безопасный контрольный объект: вертикальная рейка/рамка,
   независимо измеренные высота, поперечный размер и отмеченный отрезок. Эталон
   рядом на той же глубине. Отметить те же физические точки в приложении.
2. Записать метод контроля и его неопределённость, если известна. Для окружности
   не выдавать число за диаметр; любое преобразование и предположение записать.
3. Снять оригинал, записать дистанцию, roll/наклон камеры, освещение, перекрытия,
   оператора, прибор, сезон/облиственность для дерева. Не смешивать разные условия.
4. Выполнить не менее трёх независимых установок точек для описания повторяемости.
   Проверить 1 м/100 см и zoom/pan отдельно; это проверка программы, не контроль точности.
5. Затем реальные деревья с доступным независимым контролем. Высокую вершину
   измерять подходящим инструментом с земли; не лазать на дерево ради контроля.
   Для AR записать tracking, дистанцию, основание, версию ARCore и исходную audit-запись.
6. Записывать также отказы и пропуски. Одна строка CSV — показатель одного повтора.
   Неизвестные result/control_uncertainty оставлять пустыми, не нулями.
7. Сохранить фото/версию отчёта и заполнить [шаблон CSV](../research/geometry_field_template.csv).
   Поля app_version и algorithm_version обязательны. Отдельный experiment_id на
   условия и независимо выбранный контроль. Углы — deg, размеры — m, доли — 1.
8. Рассчитать `python tools/geometry_validation.py field.csv --output summary.json`.
   Подписанная ошибка=result-control, абсолютная=abs(error), относительная=error/abs(control)
   только при ненулевом контроле. Смещение=средняя ошибка, MAE, RMSE; выборочное SD
   результатов только при n>=2 в одной группе условий. Малое n не подтверждает точность.
   Шаблон пустой; вымышленных полевых наблюдений нет.

## Проверки и эксплуатация

Результаты автоматических тестов, точные коммиты, образ, APK и фактическое
развёртывание будут записаны после завершения проверок. Пока новая версия не
считается развёрнутой или принятой на телефоне.
