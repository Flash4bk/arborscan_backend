# Единое фото, контур дерева и эталон - AS-03 / AS-06 / AS-08

13.10.2026. Пользователь подтвердил восстановление входа и анализа после
перехода зависимостей на оплаченный VPS. Это его проверка установленной сборки
25; она не является проверкой нового объединённого режима.

## Причина и границы исправления

В сборке 25 основная кнопка анализа отправляла фото и AR, а «По эталону»
открывала отдельное измерение без выбранного фото и результата модели.
История уже поддерживала общий снимок, но связки экранов не было.

Новый клиент связывает тот же оригинал с анализом, эталоном и явно выбранной
сохранённой ревизией контура. Добавить эталон можно из основного экрана,
результата модели и сохранённого отчёта. На экране эталона можно запустить
модель на этом фото и выбрать нужное дерево касанием. Это выбор среди
готовых кандидатов YOLO, а не интерактивное создание маски по точке.
Предупреждение сервера о выборе соседнего дерева отклоняется.

Если распознавание не сработало, существующий редактор позволяет создать
контур дерева вручную. После сохранения явное действие «Использовать этот
контур в отчёте» закрепляет именно эту ревизию. Разметка эталона - отдельный
контур и отдельные отрезки. Сохранение не отправляет контур на модерацию
автоматически и не допускает его к обучению.

Размеры вычисляются по отмеченным отрезкам дерева/кроны и реальной длине
эталона. Модель имеет один класс `tree`; её единую маску нельзя объявить
отдельными масками кроны и ствола. Автоматическое определение высоты живой
кроны или DBH из этой маски не добавлено. Эталон и дерево должны находиться
примерно на одной глубине; перспектива не исправляется автоматически.
Неизвестные длины маркера и рост человека на присланных снимках не подставлялись.

По дополнительному сообщению пользователя исправлен размер точек редактора.
Обычная точка - полое кольцо радиусом 2.5 логических пикселя экрана,
первая - 3.5, активная - 4.5. Линия имеет толщину 1.25 независимо от зума.
Прежняя область захвата 14 логических пикселей сохранена отдельно;
при пересечении областей выбирается ближайшая точка. «Скрыть точки» убирает
отметки для просмотра объекта, не меняя координаты и итоговую PNG.
Кнопки подтверждения превью находятся в постоянной области диалога:
на вытянутом фото при крупном шрифте больше не нужно прокручивать до них.

## Хранение и совместимость

- Оригинальные байты, SHA256, ориентированные EXIF-размеры, отрезки и ответ
  модели сохраняются в существующем локальном журнале владельца.
  Применённая разметка переживает пересоздание экрана и остановку приложения.
  Выход из аккаунта ограничивает доступ; переустановка/другой телефон сами
  по себе этот локальный журнал не восстанавливают.
- Явное «Сохранить отчёт в аккаунте» использует существующий `/v4/reports`.
  Снимок `kind:reference` хранит исходный ответ модели, ручную геометрию,
  оригинал, условия/AR и закреплённый `correction_id`. Повторная правка
  создаёт дочернюю версию; прежние измерения модели не перезаписываются.
  При неопределённом ответе сначала повторяется тот же запрос.
  Исходная геометрия модели сохранена отдельно от ручной геометрии эталона;
  старый снимок без исходной геометрии не выдаёт её ручную замену за результат ИИ.
  ID нового запуска модели не заменяет ID цепочки сохранённых отчётов.
  Переход через просмотр источников сохраняет родительскую версию и открывает
  конкретную закреплённую ревизию, проверяя ID и SHA оригинального фото.
  Открытие связанного контура из серверной истории передаёт оригинал даже
  при отсутствии локального черновика; старый PNG не превращается в точки.
- Локальная PNG-копия выбранного контура внутри `report.contour_preview`
  связана с ID ревизии и SHA оригинала. Полные локальные данные позволяют
  экспортировать PDF без сети; чужой ID, фото или кеш другой ревизии отвергаются.
- Старые отчёты без эталона и старые эталоны без модели остаются доступными.
  SQL, серверный API и format version не менялись. Новый клиент работает
  с действующими возможностями history/reference_versions; старый API
  сохраняет существующее сообщение о недоступности серверных версий.
- Уменьшенные модельные изображения до 1600px сохраняются с явным
  `preview_width`, `preview_height`, `preview_transform`. Поля `images.width`
  и `height` связывают снимок с исходным фото; координаты не пересчитываются
  на экран. Маска модели RGBA использует alpha, исправленный PNG - бинарные
  значения. Уменьшение строго соответствует серверному round-to-even.
- PDF показывает маску и отрезки вместе, оригинал отдельно, источник
  размеров и контура явно. β и полевая точность по фото не подтверждаются.

## Что нужно для улучшения модели

1. Разметить отдельные деревья на подобных кадрах: редкие кроны, тонкие стволы,
   зима/снег, дымка, разные расстояния и несколько деревьев. Маски должны
   исключать соседей и фон; ошибки разметки проверяются существующей модерацией.
2. Отделить контроль по дереву/сцене/серии съёмки, чтобы соседние фотографии
   одного дерева не оказались одновременно в обучении и контроле. Эти два
   присланных снимка одной серии нельзя считать независимыми примерами.
3. Сравнить неизменённый baseline с кандидатом: IoU/Dice, precision/recall,
   пропуски и объединения деревьев; отдельно оценить тонкие части и перенос
   ошибки маски в геометрию. Раздельная крона/ствол требует отдельных меток.
4. Переключать модель только после такого сравнения и сохранного отката.
   Обучение, разметка этих фото и активация кандидата в данном исправлении
   не выполнялись. Новое качество автоматического распознавания не заявляется.

Для формата разметки и независимого запуска train/val/test использована
[официальная документация Ultralytics](https://docs.ultralytics.com/datasets/segment/).
Смысл порога `conf` проверен по
[документации predict](https://docs.ultralytics.com/modes/predict/).
Вывод о непригодности масок при .05 основан на наших фактических наложениях,
а план дообучения является предложением, не результатом выполненного обучения.

```powershell
& "$env:LOCALAPPDATA/Android/Sdk/platform-tools/adb.exe" -s R5CY40HNVCP shell am start -n com.example.arborscan_app/.MainActivity
```

Server/API/SQL rollback не требуется: эти компоненты, HTTPS, модель и main не
обновлялись. Для сохранного отката клиентского кода подготовить отдельный checkout
`042bcf9` (до общего режима и компактных точек, с безопасным разбором auth-ошибок),
собрать release с новым versionCode не ниже30, подписать прежней приватной
конфигурацией/lineage и установить `adb install -r`. Это подготовленный порядок,
такой rollback APK здесь не собирался и не устанавливался. Удалять приложение,
очищать данные или рассчитывать на downgrade non-debuggable APK нельзя.
Серверные версии schema1 и PNG остаются совместимыми; старый клиент может не
показать новое объединённое превью. Локальное хранение не является синхронизацией.
