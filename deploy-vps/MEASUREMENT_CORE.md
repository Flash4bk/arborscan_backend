# Измерительное ядро: результаты и порядок проверки

## Хранение: границы гарантии (уточнено при подготовке телефона)

| Данные | Место | Перезапуск / принудительная остановка | Выход и вход | Переустановка / другой телефон |
|---|---|---|---|---|
| Фото, применённая разметка эталона, единицы и вычисленный отчёт | Только ApplicationSupport текущего устройства, каталог UUID владельца | Восстанавливаются после завершённой записи | Файлы остаются; доступны после входа в тот же аккаунт | Серверной копии нет; восстановление не гарантируется |
| Несохранённый черновик контура | Только устройство, каталог владельца | Восстанавливается по существующему журналу | Тот же владелец видит свой черновик | Не синхронизируется |
| Отправленный контур: оригинал, PNG, состояние редактора, ревизии/решения | Сервер, private storage + contour_revisions | Повторно загружается GET corrections | Требуется тот же владелец либо разрешённая сервером админ-операция | Доступен после входа при сохранности серверных данных |
| Полный ответ анализа v4 и текущая AR-сессия до анализа | Память экрана; API отвечает persisted:false | Полный отчёт не гарантирован после закрытия процесса | Не является серверной историей измерений | Не переносится |
| Краткая история анализа / ar_provenance после анализа | SharedPreferences arborscan_history, максимум 30 записей | Локальный список сохраняется | Это существующий общий локальный список, не owner-каталог эталонов; выход его не очищает | Облачной синхронизации нет |
| JSON-экспорт эталона | Текст для копирования из приложения | Только если пользователь сохранил его отдельно | По месту сохранения | Самостоятельный перенос файла, не синхронизация приложения |

`adb install -r` с прежней подписью обновляет приложение с сохранением данных.
Uninstall/«Очистить данные» нельзя использовать для проверки восстановления.
Android backup/перенос производителя может вести себя иначе при переустановке,
но эта возможность здесь не проверена и не является гарантией ArborScan.
Повторный вход под тем же UUID на **этом** устройстве не равен синхронизации.
Эталон не отправляет reference_length_* в API: он полностью вычисляется локально.
Серверные reference_length_m/reference_length_px/reference_same_plane относятся
к multipart-анализу сторонних/legacy клиентов и не создают запись эталона.
AR отправляет метры, hash исходных байтов и явное подтверждение того же дерева;
хеш защищает соответствие фото запросу, а не доказывает физическую идентичность дерева.

Новая проверка при чтении эталона сверяет SHA256 (если записан) и размеры
декодированного EXIF-ориентированного фото. При несовпадении отчёт не открывается
для перезаписи. Кнопка «Сохранить отчёт на устройстве» записывает и параметры,
и вычисленные высоту/крону с версией метода; «Сохранено» появляется после записи.
При повторном открытии результат пересчитывается из сохранённых исходных точек,
а не принимается на веру из вычисленного поля. Изменение эталона пересчитывает
отчёт. Название экрана выбора отрезка показывает введённую реальную высоту/единицу:
пользователь должен отметить именно соответствующие ей основание и верх.
Автоматически проверить реальную высоту объекта по фотографии невозможно.
Разная глубина эталона и дерева даёт систематическую ошибку масштаба; не исправляется
одним отрезком, даже если контур обведён точно. Для проверки нужен общий план.

API нормализует EXIF до сегментации и ограничивает декодирование 25 МП,
байты — существующим лимитом 15 МБ. Клиент эталона использует ориентированные
размеры декодера Flutter, без обрезки. Нормализованные координаты умножаются
на ширину/высоту **исходного**, а не отображаемого изображения. Для эталона
вертикальная ось задаётся его отрезком: высота — проекция base→top на эту ось,
ширина кроны — поперечная проекция. Наклонённый ствол не превращает длину
ствола в высоту. Roll всей фотографии не меняет результат.

Подтверждение одинаковой глубины необходимо для reference-параметров API;
одного уменьшения confidence при неизвестной глубине недостаточно. Legacy
manual_scale остаётся явным внешним масштабом, его происхождение сохраняется.
Автоматическая перспективная коррекция, сегментация именно кроны и измерение
DBH по одной общей маске не реализованы. Старые эвристические пороги AR Coach
сохранены как эксплуатационные ограничения, **не** как границы погрешности.
Геометрия AR предполагает вертикальную плоскость дерева и цилиндрический ствол;
дрейф при сохраняющемся TRACKING и наклон дерева остаются полевыми ограничениями.

## Режим «По известному объекту»

Вход на экране анализа. Фото → высота м/см → контур объекта существующим редактором
→ основание/верх эталона → основание/верх дерева → края именно кроны → подтверждение
условий. Есть zoom и перестановка каждого конца отрезка. Изменение высоты/разметки
пересчитывает отчёт; неверные, нулевые и отрицательные значения не дают результат.
DBH и β не выдумываются. Источник в отчёте: «По известному объекту».

Журнал локальный, не синхронизируется на сервер. Исходные байты фото и version=1
разметка сохраняются через существующий атомарный ContourDrafts в отдельном
пространстве `ApplicationSupport/reference-measurements-v1/contour-drafts-v1/<owner>`.
Метры, система координат, размеры, SHA256 фото, точки и дата доступны в JSON-экспорте
из отчёта (выделить/скопировать). Токены не записываются в журнал. Другому владельцу
данные недоступны; смена аккаунта инвалидирует открытый экран и вложенный редактор.
Повторное открытие: История → значок линейки «Измерения по эталону».
Сохраняются применённые отрезки/контур и введённая высота; неприменённый отрезок
во вложенном экране ещё не является сохранённым изменением. Очистка данных или
удаление приложения уничтожат локальный журнал, поэтому для полевого набора
сохранять экспорт и исходные фото отдельно. Исходный отчёт/маска анализа не меняются.

## β: что вычисляется и чего пока нет

Сначала подготовлена [спецификация](../research/BETA_SPEC.md) по предоставленному
proof и поиску первоисточников. Реализованы сила по массовым долям кроны,
жёсткость EJ/l, координатная SSE, ограниченный подбор β через forward-adapter,
профиль, чувствительность и проверка уменьшения шага. Выход содержит исходные
данные/хеш/версию, рассчитанные траектории и остатки по каждому элементу/времени.

Встроенный RK4 — только свободный синтетический элемент, не модель дерева.
Полный tree-solver требует полного текста Borisevich/Vikhrenko 2018 и связанных
уравнений, проверенных начальных/граничных условий, масс, E, исходных xᵢ(t), yᵢ(t).
PDF не содержит достаточного набора; табличные массы также требуют уточнения.
Границы β задаются исследователем с обоснованием; верхний предел не берётся
из таблицы сосен. CLI отвергает реальное дерево вместо подмены его benchmark.
Неопределённость входных параметров сохраняется, но её распространение и
доверительные интервалы ещё не реализованы. Глобальная уникальность не доказана.

Пример (из корня репозитория, Python + numpy; новый выходной файл):

```powershell
python -m research.beta_identification research/synthetic_example.json beta-result.json
python -m pytest tests_v4/test_beta_identification.py -q
```

Фактический запуск примера восстановил **2.0 кг/с**, diagnostics=[].
Тест отдельно сравнивает RK4 с аналитическим решением, проверяет сходимость
и восстановление β с допуском 2e-5 на синтетике. Это не экспериментальная
валидация и не совпадение с опубликованными β деревьев. Фото/AR β остаётся null.
Путь к обычному использованию: либо дополнительный измеренный динамический
отклик и проверенный физический forward-model, либо отдельная экспериментальная
регрессия с внешней валидацией и неопределённостью. Обучение не запускалось.

## Единый протокол телефона и полевых измерений

Установка с сохранением данных и тем же debug-ключом (выбрать DEVICE_ID из списка):

```powershell
cd D:\arborscan_backend\arborscan_app
$adb = "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"
& $adb devices -l
& $adb -s DEVICE_ID install --no-streaming -r build/app/outputs/flutter-apk/app-debug.apk
& $adb -s DEVICE_ID shell am start -n com.example.arborscan_app/.MainActivity
```

1. Войти, выбрать фото с вертикальным объектом измеренной высоты на той же
   глубине, что дерево. Обвести его, отметить все три отрезка с zoom. Сравнить
   ввод 2 м и 200 см; изменение 2→4 м должно удвоить размеры, 0/NaN не давать число.
2. Применить разметку, принудительно остановить через настройки Android и открыть
   с иконки. История → линейка → запись: фото, точки, единицы и результаты сохранены.
   Повторная правка меняет только запись эталона. Смена аккаунта скрывает её.
3. На том же дереве выбрать фото **до** AR. Подтвердить связь, найти землю,
   измерить высоту и три повтора диаметра. Проверить отказ при потере tracking,
   невозможности найти горизонтальную землю, неподходящих лучах/движении;
   повторить замер. Замена фото должна сбросить AR. Крона по одному AR не появляется.
4. Контрольные размеры измерить независимым инструментом; для диаметра записать
   фактическую высоту и метод (не называть окружность диаметром). Для высоты и
   кроны явно определить основание, вершину и направление проекции. Записать
   неопределённость контрольного инструмента, не считать его абсолютно точным.
5. До сбора согласовать выборку и критерии приемки. Для каждого условия выполнить
   несколько независимых установок точек (например, три как план повторов,
   не гарантию точности); повторить дистанцию, свет, оператора и наклон камеры.
   Хранить все неудачи/отказы, не только лучший замер. Считать смещение, разброс,
   абсолютные ошибки, RMSE отдельно для каждого метода/размера/условия.
6. Экспорт: JSON эталона + оригинал фото; для AR исходная audit-запись
   `ar_provenance` в локальной истории (session/version, время, геометрия,
   photo_sha256), отдельный полевой журнал. Автоматической общей выгрузки всего
   AR-журнала пока нет. Записать tree_id, оператор, телефон/ARCore, commit/APK hash,
   контрольные размеры/единицы/неопределённости, расстояние, рельеф, ветер и свет.
7. Регрессия: старый PNG → открыть; новый контур → редактор → сохранить → ревизия
   → отправить → отклонение/причина → исправить → принять → новая правка draft.
   Это нужно повторить на новой сборке; прежнее подтверждение не заменяет проверку.

Для β дополнительно нужны сырые синхронизированные timestamps и координаты
центров масс каждого элемента с калибровкой камер/масштабом/погрешностями,
разбиение/геометрия/инерции, полные и кроновые массы, измеренный E/упругие законы,
начальные положения/скорости, условия основания, ветер/относительные скорости,
g, единицы и происхождение каждого параметра. Нужны независимые эксперименты
для проверки, версия forward-model и обоснование границ β. Одних фото таблиц,
маски, породы и высоты недостаточно.

## Совместимость и будущая выкладка (НЕ выполнялось)

SQL/формат контуров не меняется, новых миграций нет. Backend добавляет необязательные
