# ArborScan: аудит состояния и порядок дальнейшей работы

Дата начала: 11.11.2026. Итог оформлен 12.11.2026. Задачи AS-01...AS-16. Запрос пользователя:
сначала показать результаты аудита и предложить порядок работы.
Исправления, обновление production, обучение, удаление данных и публикация
не входят в этот этап. Аудит выполнялся в `codex/recognition-results`.

## 1. Вывод

У ArborScan есть работающий программный контур: фото, анализ v4, ручная
разметка, эталон/AR, сохранение, версии, модерация, карта и экспорт.
Прежние пользовательские подтверждения сохранены. Новые проверки кода и
тестов поддерживают эту оценку, но не заменяют полный вход и работу с
реальным аккаунтом на S24 сегодня.

До расширения функций нужно устранить несколько существенных проблем.
У старого API v3 найдены нарушения доступа и обработки ошибок; исторические
отчёты ещё могут выдавать неподтверждённый вердикт безопасности. Свежая
эксплуатационная проверка обнаружила отказ backup-службы и заполнение диска
VPS на 96%. Карта и подробный отчёт иногда выбирают разные данные.

Качество сегментации сложных сцен, точность геометрии, β реального дерева и
механическая устойчивость остаются самостоятельными незавершёнными задачами.
Наличие интерфейсов, тестов или изученных статей не закрывает их.

## 3. Подтверждённые дефекты и эксплуатационные проблемы

P1 - исправить прежде новых функций. P2 - включить в ближайший пакет
надёжности/согласованности. P3 - небольшое улучшение оформления.
Это вновь найденные или повторно подтверждённые проблемы существующего
кода, а не утверждение, что их внёс последний коммит.

### SEC-01 / P1. Старый feedback обходит права и модерацию

`server.py:2847-2863`, `2946`, `3020`; загрузка артефактов с `2636`.
Публичные маршруты `/api/v3/feedback` и `/api/v3/api/feedback` принимают
запрос без обязательного действительного пользователя и без проверки
владельца анализа. По известному ID можно загрузить артефакты, записать
исправления и получить `verified:true`. Для отсутствующего пользователя
записываются роль `user` и пустой ID.

Точная функция воспроизведена с синтетическим хранилищем: шесть записей,
включая verified. Наличие маршрутов подтверждено OpenAPI и Nginx;
исходный текст функции совпадает с работающим v3. Запросов записи в
production не было, эксплуатация проблемы посторонними не установлена.
Новый workflow v4 - отдельный механизм. Автоматическое обучение от этой
записи не утверждается: старый retrain worker отключён.

Нужно: обязательная авторизация и владение до чтения/записи; пользовательский
feedback не получает принятие администратора. Сохранить старые данные и
совместимость допустимых клиентов; добавить deny/owner/retry тесты.

### SEC-02 / P1. Ошибка диагностики может раскрыть ключ Pl@ntNet

`server.py:2176-2210`, особенно `2209`. Публичная диагностика возвращает
`str(exc)`. Текст транспортной ошибки может включать URL с ключом провайдера.
Синтетический ключ в тестовой ошибке действительно вернулся наружу.
Функция совпадает с production; реальные ключи не читались и ошибка
провайдера не провоцировалась. Раскрытие реального ключа не установлено.

Нужно: безопасный код ошибки и отдельная приватная диагностика. После
исправления проверить возможное прежнее раскрытие, не выводя секреты.
В новой v4-линии подобная обработка уже безопаснее.

### SEC-03 / P1. Токен передаётся в URL старого отчёта

`arborscan_app/lib/history_tab_page.dart:279-282`, `server.py:1726`.
Клиент формирует `?token=...`, хотя сервер принимает `Authorization`.
Токен может попасть в журналы запросов и другие средства наблюдения URL.
Фактические журналы с токенами не читались; конкретное раскрытие не заявляется.

Нужно: header-only передача, проверка совместимости, запрет такого URL в
регрессионном тесте и контроль редактирования логов. См. рекомендацию
[RFC 6750, раздел 2.3](https://www.rfc-editor.org/rfc/rfc6750#section-2.3).

### SCI-01 / P1. Старый отчёт выдаёт «БЕЗОПАСНО»

`arborscan_app/lib/analysis_report_page.dart:954-975`; показ первого блока
с `177`; исторические badges в `history_tab_page.dart:565-567`.
Историческая категория `низкий` превращается в крупный зелёный заголовок
«БЕЗОПАСНО». Неизвестная непустая категория превращается в «КРИТИЧНО».
Предупреждение ниже не исправляет смысл основного утверждения.

Обе ситуации воспроизведены отдельными widget-пробами на DEMO-записях.
Проблема уже отмечалась обзором 09.11; это повторное подтверждение долга.
Нужно сохранить исходные числа, но показывать исторический метод и
неопределённость без вердикта безопасности и без нового пересчёта.

### OPS-01 / P1. Таймер активен, backup-служба завершилась ошибкой

Свежий `systemctl show`: timer `active/waiting`, запуск службы
11.11.2026 03:21:36-03:39:51 UTC завершился `Result=exit-code`,
`ExecMainStatus=1`. Предыдущие успешные запуски из документации являются
историческими доказательствами, а не состоянием сегодня.

Файловая система VPS заполнена на 96%, доступно 7 295 393 792 байта
(около 6.79 GiB). Это отдельный подтверждённый риск. Доступный журнал
содержит только безопасный код `private_validation_or_runtime_error`;
причина сбоя не установлена. Нельзя объявлять нехватку места доказанной
причиной конкретного отказа.

На Windows присутствуют два датированных комплекта 22/25.10 и восемь
общих runtime-файлов. Их полная целостность, свежий SQL restore и следующий
live pull сегодня не проверялись. Существующие копии не удалялись.

Нужно: безопасно изучить приватную диагностику, установить последний
полностью проверенный комплект, расход места и восстановление регулярной
копии/переноса. Не удалять старые рабочие копии до проверки замены.

### DATA-01 / P2. Ручной вид не везде отображается

`arborscan_app/lib/survey_map_repository.dart:65-68`,
`arborscan_v4/report_history.py:151-155`.
Отчёт/PDF выбирают `species_annotation`, а карта и серверный summary
читают исходное `species`. После ручного исправления подробный отчёт
показывает новое название, список/карта могут показывать прежнее.
Для карты воспроизведено на синтетическом снимке.

Нужно единое правило отображения с сохранением исходного предсказания
и отдельного статуса подтверждения. Старые immutable summaries требуют
явной совместимости, а не перезаписи истории без решения.

### DATA-02 / P2. Карта выбирает другой размер

`arborscan_app/lib/survey_map_repository.dart:95-103`.
У объединённой версии карта выбирает старый AR-диаметр 0.40 м, а
эталонный отчёт/PDF - выбранное измерение 0.25 м. Также карта может
показать положительное число с `available:false` / `source:unavailable`.
Обе ситуации воспроизведены синтетическими пробами.

Нужно общее правило выбора источника, единиц и доступности для
замороженной версии. Исходные измерения не переписывать ради совпадения UI.

### HIST-01 / P2. Удалённая запись старой истории возвращается

`arborscan_app/lib/history_tab_page.dart:205-241`, повторная загрузка
`90-116`. Удаляется локальная сводка, затем список снова добавляет
серверную запись `/analyses/my`. При этом показано «Запись удалена».
Подтверждено чтением полного пути; разрушительное UI-действие не выполнялось.

Нужно определить семантику локального удаления/скрытия и честное сообщение.
Добавление удаления серверных данных не является автоматическим решением.

### PERF-01 / P2. Миниатюры скачивают полные контуры

`arborscan_app/lib/saved_corrections_page.dart:174-183`, `245-256`.
Список для миниатюры запрашивает detail с полным фото и PNG; Futures
удерживают байты при накоплении страниц. Уменьшение decode width не
уменьшает переданные данные. Это лишние трафик и память.
Реальная нагрузка, объём и OOM не измерялись; production не нагружался.

Нужно небольшое защищённое превью, загрузка видимых элементов и
ограниченный кеш. Оригиналы оставлять для открытия и экспорта.

### SEC-04 / P2. Старый анализ декодирует фото без предела пикселей

`server.py:2234-2238`. До ограничений выполняются `file.read()` и
`cv2.imdecode`. Nginx ограничивает файл 40 MiB, но это не ограничивает
память распакованного изображения. У v4 есть собственные byte/pixel limits.
Большое опасное изображение не отправлялось, OOM не воспроизводился.
Отсутствие лимитов установлено в проверяемой ветке; весь `analyze_tree`
отдельно не сверялся по SHA с работающим контейнером. Маршрут Nginx
сам по себе не доказывает отсутствие всех ограничений deployed-функции.

Нужно ограничивать файл и размеры изображения до тяжёлой обработки;
согласовать ошибки с клиентом и сохранить сервер входа работоспособным.

### SCI-02 / P2. Старый публичный анализ ещё выдаёт неподтверждённые оценки

`server.py:2211`, `2250`, `2498-2510`; helper `1153-1175`.
Старый v3-маршрут может подставить прямоугольную маску, типовой масштаб,
эмпирический β и риск. Чистая функция в AST-пробе возвращает β=5 при
нулевой площади и β=45 при неизвестной породе и тестовой площади 10.
Наличие `/analyze-tree` в работающем v3 и текст helper подтверждены.
Вызов inference на production не выполнялся.

Обычный новый Flutter-анализ использует v4; эту проблему нельзя приписывать
его текущему пути. Нужно решить судьбу старого маршрута и маркировку
недоступных величин, сохраняя управляемую совместимость старых клиентов.

### OPS-02 / P2. Обучающий worker не запущен

Фактический `selfhost-20261012t140855z-worker-1` имеет состояние `created`,
нулевой `StartedAt`; этот контейнер создан 12.10 и ни разу не запускался.
Это не обычное ожидание задач
в проверенном `quality_worker.py:89-98`. Обычный анализ фото работает без него.
Назначение текущего приватного selfhost Compose и намеренная остановка
не установлены; регрессия конкретного обновления не заявляется.

Нужно определить разрешённый режим обучения, проверить очередь/heartbeat
в отдельном контуре. Запуск ради проверки недопустим: он может начать
обработку сохранённых задач. В этом аудите worker не запускался.

### REL-01 / P2. Повторная сборка может получить другой runtime

`requirements.txt:1`, `deploy-vps/requirements.v4.txt:1`,
`deploy-vps/Dockerfile.v4:23`: большинство зависимостей не закреплены
точными версиями/хешами. Сохранённые образы имеют фиксированный SHA,
но новая сборка того же исходного коммита не гарантирует те же библиотеки.

Фактические версии контейнеров прочитаны через `importlib.metadata`.
Они отличаются от локальной тестовой среды. В обоих зарегистрированы
`opencv-python` и `opencv-python-headless` разных версий; фактический
импортируемый набор `cv2` по metadata не установлен.

Запрос выбранных версий к OSV завершился `ConnectionError`. Отсутствие
известных уязвимостей не подтверждено, конкретные CVE не заявляются.
Нужно закрепить согласованный runtime и повторить проверки/advisory scan
в изолированном кандидате; production-пакеты не обновлять вслепую.

### PDF-01 / P3. Пояснение показателя переносится отдельно

`arborscan_app/lib/report_pdf.dart:296-316`.
В длинном DEMO PDF на странице 3 остались заголовок и значение показателя,
на странице 4 - источник и причина отсутствия данных. Текст не потерян.
Нужно держать начало пояснения вместе с показателем или повторять подпись.
