# Серверные отчёты и единая вкладка истории

## Состояние этапа

Рабочая ветка `codex/server-history` от `95ad5de`. Предыдущий измерительный
пакет включён fast-forward в main и отправлен. Новая история в main не включена.
В задании приведено общее подтверждение всех ручных проверок, но в переписке
пользователь явно отложил полевую проверку AR. Поэтому подтверждёнными остаются
эталон, одинаковые результаты 1 м / 100 см и открытие после остановки приложения.
Контрольные размеры, погрешности и условия не придуманы. β отложен;
исследовательский модуль сохранён без изменений.

## Схема

Существующий `analysis_id` связывает отчёт и контуры. Для v3 сохраняется таблица
`analyses`, её владелец и неизменённые endpoints. V4 раньше возвращал
`persisted:false`; endpoint анализа продолжает это делать и ничего не сохраняет
без отдельного действия пользователя. Таблица `report_versions` расширяет
этот идентификатор неизменяемыми версиями (UUID version_id, parent_id, владелец,
SHA256 снимка, SHA256 оригинала, ссылка на конкретный correction_id).
Вкладка истории показывает эти версии, локальные отчёты и прежние v3-записи;
контуры остаются доступны из той же вкладки.

Полный снимок — JSON в существующем **приватном** bucket контуров, отдельный
префикс `report-versions/<owner>/<sha256>.json`. В нём исходные байты фотографии
(base64), её SHA256 и EXIF-ориентированные размеры, координатная система,
полный ответ анализа/результат эталона, разметка, AR-привязка, время,
источники и единицы. Ссылки с истекающим сроком не используются. Файл выдаётся
только через авторизованный GET версии с фильтром владельца; знание ID недостаточно.
Администратор не получает доступ ко всей новой истории другого пользователя.
Полномочия существующей модерации не изменяются.

Снимок, отправленный клиентом, явно отмечен `user_supplied_snapshot_not_independently_verified`:
это не криптографическое доказательство выполнения модели. Новый ответ анализа
содержит дату, версию измерительного алгоритма и фактическую версию сегментации;
старым результатам эти сведения не приписываются. Вид/показатели и происхождение
сохраняются из фактического ответа. Эталон дополнительно проверяется и пересчитывается
сервером из исходных координат. β остаётся null с причиной. DBH допустим только
при указанной высоте измерения 1,3 м.

GPS/погода/почва необязательны. В новом envelope `environment` каждое полученное
значение имеет `value`, `source`, `retrieved_at`; отсутствие данных не мешает.
Текущий v4-экран не получает эти внешние данные: фиктивные значения не добавлены.
Прежние v3-отчёты открываются своим сохранённым JSON, включая имевшиеся GPS,
погоду и почву. Новых запросов погоды при открытии снимка нет.

## Атомарность и незавершённые операции

Оригинал и снимок загружаются одним immutable JSON. До подтверждённого чтения
и проверки SHA256 запись не индексируется. RPC `save_report_version` в одной
транзакции блокирует владельца, проверяет повтор UUID/хеша, родителя, оригинал
и принадлежность связанного контура. Ограничения unique обеспечивают один
корень на анализ и одного ребёнка на родителя; второй редактор получает 409.
Новое намеренное выполнение анализа имеет новый analysis_id даже для того же фото.
Повтор той же операции возвращает прежнюю версию. Изменение payload при том же
version_id отклоняется. Сохранение отчёта не меняет ни статуса, ни решения контура,
ни допуска к обучению.

Сбой до индексации может оставить недоступный из истории объект. Повтор запроса
использует тот же хеш и подтверждает существующий объект; автоматического удаления
нет. Конфликтующая незавершённая загрузка остаётся приватной. Будущий сборщик мусора
должен делать read-only инвентаризацию, учитывать ссылки всех версий и резервную
копию; сейчас такого сборщика нет. Это намеренное ограничение без риска удаления
оригиналов. Удаление синтетических fixtures ограничено аккаунтами конкретного smoke-run.

## Локальное хранение и совместимость

`ApplicationSupport/report-history-v1/contour-drafts-v1/<owner>` — атомарный журнал
полного снимка и UUID операции. Он сохраняется до HTTP и переживает перезапуск.
При потере подтверждения предлагается повтор; успех показывается только после
saved:true/persisted:true и совпадения version_id. Неотправленная версия остаётся
локальной; сохранённые локальные копии доступны и при сетевой ошибке.
Существующий журнал эталонов сохранён; кнопка отправки публикует его явно.
Открытие серверного эталона восстанавливает исходные точки в существующем редакторе;
новая правка сохраняется ребёнком выбранной версии, не переписывает прежнюю.

Оригиналы локально автоматически не удаляются. Выход закрывает приватные экраны
и инвалидирует незавершённые ответы. Вход в тот же аккаунт на том же устройстве
возвращает локальные записи. Серверные версии и файлы доступны на другом устройстве
после входа. Неотправленные данные не гарантируются после удаления приложения,
очистки данных или смены телефона. Это не резервная копия средствами Android.

Старый общий `arborscan_history` не имел владельцев и оригиналов. Его данные
оставлены на диске, но записи с неизвестным владельцем не показываются новому
аккаунту и автоматически ему не присваиваются. Прежние серверные v3-записи
загружаются с проверкой владельца. Если старая краткая локальная запись не имеет
оригинала/полного отчёта, восстановить их или отправить как полный снимок нельзя.
Это ограничение прежнего формата, а не миграция с выдуманными полями.
Новые краткие записи помечаются владельцем; карта также исключает чужой кеш.

Старые клиенты и PNG endpoints не изменены. Новый клиент со старым API сообщает,
что серверная история недоступна, сохраняя локальное редактирование/данные.
Возврат прежнего API совместим с дополнительной таблицей: она просто не используется.

## Миграция и проверки

`002_server_history.sql`: недеструктивная, повторно применимая, RLS включён,
anon/authenticated не имеют доступа к таблице/RPC. Все owner IDs сервер получает
из действующей сессии, а не из формы клиента.

Пользователь подтвердил применение файла и `server_history_version() = 1`.
Агент независимо получил 1 через production PostgREST RPC. DDL не выполнялся
агентом напрямую. В локальном PGlite выполнены миграция дважды, реальные SQL
ограничения, конфликты, ACL, изоляция родителей и неизменность модерации.

До переключения: локально 56 backend tests, 1 пропуск модуля с ultralytics,
3 subtests; два прежних deprecation warnings. Flutter: 38 passed;
analyze: прежние 106 замечаний (0 errors, 7 warnings, 99 info).
Новый RenderFlex overflow найден тестом и исправлен; повтор прошёл.

## Ручная приёмка нового этапа — ожидается

1. Создать эталон, сохранить в аккаунте, остановить приложение, открыть в истории.
2. Изменить эталон и сохранить ребёнка; открыть обе версии с прежними размерами.
3. Сохранить контур, связать конкретную ревизию новой версией отчёта, проверить
   статус/решение через существующую модерацию.
4. Отключить сеть, сохранить локально, перезапустить, включить сеть и повторить
   отправку; убедиться, что повтор не добавил вторую одинаковую версию.
5. Переключить два аккаунта, проверить отсутствие чужих записей/фото.
6. Открыть старую серверную запись и старый PNG.
7. При наличии второго устройства войти в тот же аккаунт и открыть файл/разметку.

Переустановка и очистка данных для этого не требуются. Недоступная проверка
второго устройства и отложенная полевая точность AR не считаются пройденными.
