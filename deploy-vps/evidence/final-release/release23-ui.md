## Прямое обновление 18 → 23: данные и повторное открытие

В настоящем APK18 (`1.3.0-readiness.1cf6ce3`) через обычный интерфейс выполнен
вход разрешённого DEMO пользователя. Android PhotoPicker выбрал собственный
синтетический JPEG 256×384; фото помечено DEMO. Его SHA-256:
`1717ce24ebd3e5ff8eb4c97ba061e1d177f68af73d72af012abb633f914e6b76`.

крона 176 px. Обычной кнопкой сохранён локальный отчёт, показывающий
**5.00 м / 2.93 м**. Повторный выбор фото создал отдельный незавершённый
черновик с вводом **3 м**, без готовых отрезков. Приложение остановлено,
выполнен guest `sync`; серверные записи этим сценарием не создавались.

После сохранного прямого обновления, повторной установки того же APK23 и

сохранённого контура; отдельный черновик восстановил **3 м** и состояние
незавершённой разметки. Сравнение восьми файлов по SHA выполнено в отдельной
проверке установки; семантическая проверка интерфейса не подменяет его и не
заявляет отдельное пиксельное сравнение фото.

## Независимые API проверки контролируемой модерации

Для новой уникальной семьи создана только собственная синтетическая запись:
оригинал DEMO, треугольная PNG-маска и точное состояние редактора v1.
Черновик и отправка (`submitted`) выполнены настоящими авторизованными HTTPS
запросами. Это **API seed, не создание через Flutter**. Повтор тех же байтов
и родителя использовал ту же ревизию. Второй разрешённый DEMO пользователь
получил **HTTP 404** при чтении этой записи; роли и identities не менялись.
У тестового артефакта «admin» фактическая серверная роль `user`, очередь
проверки вернула **HTTP 403**. Этот отказ не является проверкой решения
администратора. Через сохранённый легитимный аккаунт S24 другой агент затем
отклонил только новую allowlisted DEMO ревизию после сверки точных ID в UI,
с причиной `AS16_DEMO23_retest`. Свежий авторизованный GET автора подтвердил
`rejected`, ту же причину, ровно одно событие отклонения, автора решения и
время; автор решения отличается от автора контура. Это первоначальное подтверждение API
после решения S24; последующий настоящий авторский интерфейс описан ниже.
Публичный безопасный JSON `moderation23-root-rejection.json`:
SHA `c079b1ad6cdfbb227b5278a770b8817f016d70ae22d6adb567424f7fe71422f8`.
Старые решения и реальные записи не менялись.

Не выполнялись фиксация датасета, экспорт в обучение, запуск обучения или
замена модели. `eligible_for_training:false` в overlay сам по себе не
доказывает исключение экспортёром. Принятие контура также не подтверждает
физические измерения и β.

## Выполненный авторский цикл и два решения S24

Обычный email-вход разрешённого DEMO автора выполнен в APK23. Автор увидел
отклонение и причину в Flutter. После настоящего изменения вершины контура
несохранённый черновик восстановлен через историю после force-stop. Два
быстрых нажатия Save создали ровно одну дочернюю ревизию; независимый HTTPS
GET подтвердил родителя, изменённое editor state и неизменный оригинал.
Автор отправил её на проверку. S24, сохранив реальный легитимный аккаунт,
принял только эту точно сверенную новую DEMO revision. Автор открыл accepted.
Новая правка accepted создала третью revision draft; accepted-parent и
rejected-root сохранили статусы. Автоматического принятия/обучения нет.

Отдельная правка устаревшего родителя и повтор сохранения реально показали
конфликт: черновик остался на экране, серверная цепочка из трёх ревизий не
изменилась. Старый pending_review PNG открыт read-only с оригиналом и маской;
видна явная кнопка создания нового контура, прежние точки не заявлены.
Все точные owner/family/revision IDs проверены приватными allowlists перед
решениями; публичный [workflow JSON](moderation23-workflow.json) содержит
только безопасные assertions. [Причина в UI](author23-rejection.png),
[конфликт и сохранённый черновик](author23-conflict-draft.png).

## Эталон, выбранные версии и реальные PDF

Выбрана собственная server-v2 с эталоном2м. Через обычный UI создана новая
версия с3м; до серверного сохранения force-stop и открытие из локального
журнала восстановили ввод/отрезки/результат12.15м и7.79м. Два быстрых Save
дали одну v3. Parent/photo/coordinate state сверены свежим GET, не только
по сообщению «Сохранено». Открытые v2/v3 экспортированы в настоящем SAF;
файлы выгружены и device SHA совпал. v2 содержит8.10м/5.19м, v3 —12.15м/7.79м;
масштаб1.5, фото и точки одинаковые. Provider snapshots06.10 сохранены, их
даты не переименованы в свежую погоду. [PDF QA](pdf23-qa.md):32/32 каждый,
8/8 сравнений и все10 страниц отдельно просмотрены.

На S24 отдельно экспортирован разрешённый старый DEMO AS09 report: реальный
SAF save, Download/pull SHA, Drive PDF viewer из app dialog, share-sheet/Back
без адресата/отправки и SAF cancel. Его5страниц прошли12 содержательных

фото с серверными исходными байтами — [точная граница](s24-pdf23-qa.json).

## Сеть, карта, источники, GPS и анализ

В собственном AVD сеть выключена, приложение остановлено, запись открыта
из локального журнала, реальный PDF просмотрен. Сеть восстановлена до
исходного состояния; выбранная v3 снова открыта через обновлённую серверную
историю с признаком account-saved, а не offline cache. S24 сеть не менялась.
[Actual offline proof](offline23.json).

На карте actual Google Maps tiles и DEMO marker. UI «Получить текущие условия»
загрузил OpenWeather07.10 21:24:38UTC и SoilGrids21:24:42UTC для контролируемой
DEMO точки50.2/10.2. Partial soil, неизвестная observation date/uncertainty,
250м и слой0–5см показаны явно; weather14.54°C/0.36м/с, soil clay29.5%/sand19.5%/
carbon54.9g/kg. Draft сохранён только локально; server-save не нажимался.
[Источники](provider23.json), [weather](provider23-weather.png),
[soil](provider23-soil.png).

AVD GPS предложил старое последнее положение, оба раза отменено. S24 отдельно
дал свежий location-result dialog0мин/±17м; он отменён без принятия координат
или server-save. [Safe proof без личных координат](s24-gps23.json).
Это программный query/cancel, не точность GPS/полевых измерений.
Native picker выбрал собственный synthetic JPEG, actual Analyze завершился
«Дерево не найдено» без искусственной маски; запись на устройстве создана,
server-save не нажимался. [Analyze](analysis23.json), [экран](analysis23-no-tree.png).

Исторические результаты APK19 не переименовываются в проверки APK23. Настоящий
Google-вход разрешённого аккаунта отдельно выполнен на
[API36/new signer](google23-native36.json) и [API24/old signer](google23-native24.json),
включая server session/history/restart/logout/relogin/cancel/offline/retry. Это
legitimate flow старого production handler, не rollout подготовленной security policy.

После UI три новые synthetic DEMO ревизии изолированы существующим exporter marker.
Менялось только purpose; изображения, редактор, ревизии и SQL решения совпали.
Сам runtime exporter отверг все три для обоих типов модели, public HTTPS readback
подтвердил durable marker. Это не создание снимка/обучение и не наследование marker
будущими правками: [служебная изоляция](moderation23-test-quarantine.json).
