## Оформление и навигация

Использованы существующий логотип и согласованное в задании направление.
Названные в старом плане DOCX-макеты не были доступны; их содержание не
восстанавливалось по названиям. Тема светлая, матовая: фон `#F5F5EF`, белые
поверхности, оливковый `#526238`, текст `#242A20`, вторичный `#5C6456`.
Без свечения/стеклянного размытия. Статусы имеют текст и значок, а не только цвет.
Общие карточки, поля, диалоги, кнопки и интервалы объединены в AppTheme/Ui.
Прежнего пользовательского переключателя тем нет; новый не добавлялся.

Камера и галерея — крупные действия, на узком экране/большом шрифте располагаются
последовательно. Заставка показывает прежний логотип с первого кадра и короткий
переход без искусственного таймера. Четыре подписанные вкладки больше не
перекрывают контент и сохраняют введённые данные. При повторном входе история,
карта и профиль перечитывают данные, не сбрасывая поиск/фильтры. Ответ статистики
старой сессии не применяется к новой.

В режиме входа/регистрации кнопки переносятся целиком (Wrap/ChoiceChip),
не разбивая слово на крупном шрифте.
В обратной связи строка статуса/масштаба переносится, ошибка диапазона числа
показывается до четырёх строк. Списки выбора моделей/таксонов растягиваются
по ширине и допускают многострочные пункты. Эти изменения устраняют конкретные
переполнения при 160/200% шрифта; значения API и проверки диапазонов прежние.

У редактора маски инструменты вынесены из рабочей области, подтверждение —
в нижнюю SafeArea; верхняя панель прокручивается. У разметки отрезка есть
предупреждение о неприменённых правках, прокрутка длинных переключателей и
ограниченная высота инструкции. Координаты, EXIF, масштаб, PNG, формулы,
ревизии и исходные измерения не изменены. Локальное и серверное сохранение,
недоступные показатели, источник размеров, подтверждение вида и прогноз модели
по-прежнему различимы. Состав и оформление самого PDF не менялись.

### Проверка окончательного APK на S24, 01.10.2026

descriptor с `ArImage[]`, а ARCore 1.50 предоставляет `android.media.Image[]`.
Успешный возврат из недоступной сессии в AVD не проверял этот путь rendering.
Сбой исправлен в ad15870 переключением lighting renderer/Session на
`AMBIENT_INTENSITY`; координаты, tracking и расчётная геометрия не менялись.

Success, прежние applicationId и сертификат, точные versionName/versionCode
проверены. Непосредственно до/после установки, до запуска приложения:
**37/37 файлов, 0 удалённых, 0 добавленных, 0 изменённых** в `files/shared_prefs`.
Это отдельное доказательство обновления без удаления данных, не обещание,

не выполнялись; действующий аккаунт администратора сохранён.

Холодный запуск +7 завершился успешно за **1724 мс**. В настоящей AR-сессии

## Исправление найденного AR-сбоя

На Android API 36 эмулятора в caa65c8 запуск встроенной установки ARCore
падал с SecurityException в registerReceiver. Прямую зависимость ARCore 1.31.0
заменили на 1.50.0; Sceneform и собственная расчётная геометрия прежние.
Официальный [выпуск 1.50.0](https://github.com/google-ar/arcore-android-sdk/releases/tag/1.50.0)
указывает поддержку target API 36. Результат повторного пути установки/отмены
и ограничения реальной AR-сессии указаны в журнале устройства. Это исправление
конкретного обнаруженного сбоя, а не новая измерительная модель.

Следующее исправление b34488f обрабатывает callback Sceneform о недоступной
AR-сессии: отмена установки возвращает обычную отмену, остальные отказы —
понятное русское сообщение на экране фото. Пустой неработающий экран больше
не остаётся при отказе конструктора Session. Listener установлен до первого
onResume, повторное завершение защищено; bridge не создаёт измерительный результат.
Отдельные ошибки ArSceneView.resume могут поглощаться самой Sceneform без этого
callback; их обработка не подтверждена этим исправлением. Прежние
незавершённые нативные точки AR не переживают уничтожение процесса.

На S24 в b34488f+6 был отдельно найден HDR-сбой совместимости Sceneform/ARCore.
ad15870 задаёт `arSceneView.lightEstimationConfig = LightEstimationConfig.AMBIENT_INTENSITY`
до первого resume. Это свойство задаёт ветку освещения renderer и конфигурацию
Session, поэтому несовместимый вызов HDR cubemap не выполняется. В ambient-ветке
используется сохранившийся `getColorCorrection(float[], int)`; синхронизация
конфигурации проверена по исходникам Sceneform v1.23.0 и bytecode локальных AAR.
На настоящем S24 +7 путь Session/frame rendering и повторный вход прошли без
прежнего падения, в пределах описанного выше комнатного опыта. Меняется
освещение виртуального маркера; формулы размеров, pose, plane/hit tests и модель
не меняются. [Setter Sceneform v1.23.0](https://github.com/SceneView/sceneform-android/blob/v1.23.0/core/src/main/java/com/gorisse/thomas/sceneform/ArSceneView.kt).

Сборочное окружение: AGP 8.9.1, Gradle 8.11.1, Kotlin 2.1.0, JDK 21,
Java/Kotlin bytecode 17, compileSdk/targetSdk 36, minSdk 24. Минимальные версии
AGP/Gradle для API36 выполнены по [таблице Android](https://developer.android.com/build/releases/about-agp#api-level-support),
JDK21 поддерживается [Gradle с 8.5](https://docs.gradle.org/8.5/release-notes.html#full-java-21-support).
Kotlin 2.1.0 находится вне полностью протестированного диапазона этих Gradle/AGP
по [матрице Kotlin](https://kotlinlang.org/docs/gradle-configure-project.html#apply-the-plugin):
фактическая сборка и тесты проходят, безусловная поддержка всей матрицы не заявляется.
Sceneform 1.23.0 остаётся прежней; dependencyInsight подтверждает выбранную ARCore1.50.0.

## Оставшиеся границы

- Визуальное одобрение пользователя не получено. Оно не записывается за него.
- Повторный фото → production-анализ → сохранение и реальная серверная модерация
  в новом оформлении не заявляются выполненными: изолированная эмуляторная сессия
  истекла, пользовательский аккаунт не заменялся. На S24 +7 подтверждён только
  отдельно описанный набор сценариев. Затронутые
  состояния/права/ревизии проверены тестами; они не подменяют этот UI-цикл.
- Live AR-камера/tracking/постановка в окончательном UI подтверждены комнатным
  опытом S24 +7. Полный протокол высоты/DBH, контрольные размеры и точность не
  проверялись; прежняя геометрия проверена Kotlin-тестами, расчётный код не менялся.
  В фактическом базовом AnalyzePage AR требует выбранное фото; это существующее
  расхождение с желаемым сценарием AS-03, не новый запрет редизайна. Оно
  зафиксировано, функциональный AR-проект в AS-15 не расширялся.
- Камера, Google-вход и внешние Maps не получили полноценного нового end-to-end
  теста. Живая камера AR проверена отдельно; это не проверка Photo Capture.
  Доступные альтернативы и реальные результаты указаны выше. Регистрация S24
  в гостевом режиме не проверялась; профиль действующего аккаунта при 200% проверен.
- Синтетические размеры/комнатный UI не подтверждают точность AS-13; β,
  механическая модель и обучение не реализованы этим этапом.
